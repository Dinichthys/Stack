# Структура данных Стек

Задача заключалась в реализации такой структуры данных, как стек. Также, надо было написать защиту для него, преднамеренно оставив одну лёгкую и одну сложную уязвимость.

 После этого, нужно было обменяться программами с другим человеком и найти уязвимости, спрятанные в его коде.

## Реализация стека

При создании стека динамически выделяется память под структуру и сам стек. Однако, у пользователя нет прямого доступа к полям структуры, так как ему возвращается не указатель на структуру, а результат **побитового исключающего ИЛИ** (**xor**) с каким-то заранее заданным ключом.

Более того, если пользователь запросит слишком маленький стартовый размер стека, то его значение будет увеличено до некоторой константы. Если же пользователь запросит слишком большой размер, то наоборот - размер стека уменьшится до другой некоторой константы.

При добавлении и взятии элемента стека, его размер, по необходимости, изменяется с помощью ```realloc```.

Так же, при использовании каждой функции, на входе и выходе из неё происходит проверка стека на валидность с помощью тех или иных признаков, в зависимости от уровня включенной защиты.

Для отладки можно отдельной функцией вызвать описание (**dump**) структуры и содержимого стека.

## Защита стека

### Инкапсуляция

Как уже упоминалось выше, у пользователя нет прямого доступа к полям данных структуры. Это реализовано благодаря возврату значения, являющегося результатом применения операции **xor** к адресу структуры и ключу. Поэтому, при входе в каждую функцию, кроме функции изменения размера стека, из ключа получается указатель, с которым и проводится дальнейшая работа.

Данная защита нужна для того, чтобы пользователь не испортил поля структуры и значения элементов стека напрямую. Такая защита обязывает его работать исключительно через специальные функции.

### Хеширование

Для включения данной защиты нужно использовать ```-DHASH_PROT``` при компиляции. Данный дефайн добавляет поля для хранения хеша структуры и хеша стека в его структуру, а так же добавляет вызовы проверки хеша на входе и пересчёт хеша на выходе из функций. Хеширование использовалось самое простое - сумма всех подряд идущих в памяти байтов, содержащихся в месте, которое хешировалось.

Данная защита необходима для того, чтобы проверять, что стек не был изменён вне функции, а работа с ним всё ещё возможна.

### Канареечная защита

Для включения данной защиты нужно использовать ```-DCANARY_PROT``` при компиляции. Данный дефайн изменяет способ выделения памяти под стек - теперь перед и после массива стека и его структуры, но не как её поля, а как отдельно расположенные в памяти байты, лежат специальные значения, называемые канарейками, которые проверяются на валидность на входах в функции.

Данная защита нужна для того, чтобы не допустить ошибок по типу ```buffer overflow``` при работе со стеком и его структурой.

## Использование стека

Для задания типа элемента стека нужно использовать ```typedef``` на имя типа **stack_elem**.

Для создания нового стека нужно воспользоваться макросом ```STACK_INIT(stk, number)```, где **stk** - имя переменной, которую вы хотите объявить для работы со стеком (объявление происходит внутри макроса, поэтому заранее её объявлять не надо), а **number** - стартовое количество пустых ячеек в стеке.

Для добавления и взятия элемента стека нужно использовать функции:
``` C
enum STACK_ERROR stack_push (const size_t stack_encode, const stack_elem element);
enum STACK_ERROR stack_pop  (const size_t stack_encode, stack_elem* const element);
```
Здесь ``stack_encode`` - переменная, полученная при создании стека, его идентификатор, а ``element`` - элемент для добавления или извлечения из стека, в зависимости от функции.

Для того, чтобы увидеть описание стека и его содержимого нужно использовать ``DUMP(stk)``, где ``stk`` - идентификатор стека, полученный при его создании.

Для просмотра ошибки, при её возникновении, нужно воспользоваться функцией:
``` C
const char* decoder_error   (const int error);
```
Данная функция принимает номер ошибки, а возвращает её значение в виде строки.

## Возвращаемые значения функций

|Имя ошибки        | Код ошибки | Описание
|:---:             |:---:       |:---:
|    DONE          | 0          | Корректное завершение
|    CANT_CREATE   | 1          | Не удалось создать стек
|    CANT_DESTROY  | 1 << 1     | Не удалось удалить стек
|    CANT_RESIZE   | 1 << 2     | Не удалось изменить размер стека
|    CANT_PUSH     | 1 << 3     | Не удалось добавить элемент в стек
|    CANT_POP      | 1 << 4     | Не удалось достать элемент стека
|    CANT_DUMP     | 1 << 5     | Не удалось вывести информацию о стеке
|    BAD_STACK_PTR | 1 << 6     | Указатель на стек не валидный
|    BAD_FILE_NAME | 1 << 7     | Указатель на имя файла, в котором был создан стек, не валидный
|    BAD_LINE_NUM  | 1 << 8     | Номер строки файла, на которой был создан стек, не валиден
|    BAD_NAME      | 1 << 9     | Имя переменной, обозначающей идентификатор стека и объявленной при создании стека, не валидно
|    BAD_SIZE      | 1 << 10    | Размер стека не подходит под описание нормальной работы программы
|    BAD_CAPACITY  | 1 << 11    | Размер памяти, выделенной под стек, не подходит под описание нормальной работы программы
|    BAD_DATA      | 1 << 12    | Значение указателя, хранящегося в структуре стека, на массив, являющийся стеком, не валидно
|    BAD_STACK     | 1 << 13    | Значение ошибки, означающее, что при верификации стека все проверки были провалены
